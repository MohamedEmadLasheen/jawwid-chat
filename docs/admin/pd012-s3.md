# PD-12 S3: Instalment Payments

Record: `docs/product/JAWUID-CHAT-PRODUCT-BOUNDARY.md` §4 PD-12 §1, and PD-10 §1.
Migration: `supabase/migrations/20261019180000_chat_pd012_s3_billing.sql`.
Code: `apps/api/src/billing`, `apps/admin-web/src/features/instalments`.

## What the page is

One list of Jawwid Core's invoices for the families the viewer may see. Chat reads
the invoices **when the page is requested** and stores nothing about them: no
table, no cache, no audit or log line. The frozen `chat.subscription` mirror is
not revived. Paying stays in Core.

Each row shows:

| Column | Where it comes from |
|---|---|
| Responsible account | The invoice's payer (`parent_id`), shown by the family's primary contact's name in Chat (`family.core_parent_id`). |
| For | The child Core names (`child_id`, matched to `learner.core_child_id` **inside the payer's family only**), or "The family". A child Chat does not have in that family is shown as unknown, never matched elsewhere. |
| Amount, due date | Core, as sent (`amount_minor`, `currency`, `due_date`). |
| Status | Derived: **Overdue** (open, due before today), **Due today**, **Upcoming**, **Paid**. Today is the academy's day in `schedule.timezone`. |
| Responsible supervisor | A child's invoice: that child's PD-8 supervisor. A family invoice: the family's **billing supervisor**. Nothing else, and nothing guessed. |
| Open conversation | A direct conversation of the family that this viewer may open (`chat.staff_conversation_access`). |

Order: Overdue (oldest first) > Due today > Upcoming (soonest) > Paid (latest
first). Paid invoices are hidden unless *Show paid* is ticked. Filters: *All*,
*Mine* (I am the responsible supervisor), *No billing supervisor* (no responsible
supervisor, which is the Operations Manager's work list).

## Who sees it (`billing.family_read`)

| Viewer | Families |
|---|---|
| Operations supervisor (admin/coverage, `chat.department_member` of Operations) | Those they reach under PD-8 (`chat.staff_reaches_family`, so an active backup link counts). |
| Operations Manager | Every family in the organization, including those no supervisor reaches. |
| super_admin | Every family in the organization. |
| Teachers and Sales departments, teachers, parents | None. `COMM.BILLING_DENIED`. |

Chat asks Core **only** about the parents of the families in scope, and drops
anything Core returns for a parent it did not ask about. A Core bug cannot widen
a supervisor's view.

## The billing supervisor

`chat.family_billing_supervision` is one row per family, holding the Operations
supervisor responsible for its family invoices.

- Set or cleared by the **Operations Manager** or the **super_admin**, with a
  reason, from the invoice row (`POST /families/:id/billing-supervisor
  {supervisorId | null, reason}`). Audited as `family.billing_supervisor_set` or
  `family.billing_supervisor_cleared`.
- **Must supervise one of the family's children** (a primary Operations
  supervisor, active, same organization). The row opens the family's
  conversation, and a responsible supervisor who could not open it would be
  responsible for nothing. The trigger refuses anyone else (409
  `COMM.ORG_STRUCTURE_INVALID`).
- **Cleared by the database** when a change to the children's supervision leaves
  them supervising none of the family's children: a reassignment, a child
  removed, or a child moved to another family. That holds for every writer, and
  each clear is audited with no actor. The family returns to *No billing
  supervisor*; the manager chooses again.

## The Core contract Chat asks for

Core does not publish an invoice read API yet (PD-10 open item 2). Until it does,
the page says **"Jawwid Core is not connected yet"**, which is different from
"Nothing due". This is Chat's requirement; only
`apps/api/src/billing/core-invoice-source.ts` changes when Core ships it.

```
POST {CORE_BASE_URL}/integration/chat/invoices/query
Authorization: Bearer {CORE_API_KEY}
{ "parent_ids": ["<core_parent_id>", ...], "include_paid": false }      (at most 200 per call)

200 { "invoices": [ {
        "id": "<Core invoice id>",
        "parent_id": "<core_parent_id>",
        "child_id": "<core_child_id>" | null,     null = a family invoice
        "amount_minor": 150000,                   integer, minor units
        "currency": "EGP",                        ISO 4217
        "due_date": "2026-10-25",
        "status": "open" | "paid" | "void",       void is never shown
        "paid_at": "2026-10-02T09:00:00Z",        optional
        "label": "October, Quran + Arabic"        optional
} ] }
```

A malformed invoice is dropped, not guessed at. If Core is unreachable, slow
(`CORE_TIMEOUT_MS`, default 5000) or answers an error, the page shows
`COMM.BILLING_CORE_UNAVAILABLE` (502), never an empty list.

**Switching it on:** set `CORE_INVOICES_ENABLED=true` together with
`CORE_BASE_URL` and `CORE_API_KEY`. `CORE_BASE_URL` alone does nothing, because
`.env.example` already carries a placeholder for it.

## Routes

| Route | Who |
|---|---|
| `GET /instalments/access` | Any staff member: `{billingReader, canAssignBillingSupervisor, coreConnected}`. The Admin Web shows the *Instalments* entry only when `billingReader` is true. |
| `GET /instalments?responsible=all\|me\|none&paid=true` | Readers. |
| `GET /families/:id/billing-supervisor` | Readers who reach the family: the current one and the candidates (the children's supervisors). |
| `POST /families/:id/billing-supervisor` | The Operations Manager and the super_admin. |

The super admin reaches the page as the Admin Portal's *Instalment payments*
section (`/admin/instalments`).
