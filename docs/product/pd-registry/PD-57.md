## Decision 2026-11-04 (owner): every responsible manager is told (A-2a)

When a family blocks a user, notify ALL relevant managers responsible for the
supervisors assigned to that family's children:

1. Find all supervisors assigned to the family's children.
2. Find the managers responsible for those supervisors.
3. Notify every one of them, even across departments.
4. No duplicate notice to the same manager.
5. Record the block in the administrative audit log.
6. Least privilege: being notified grants the manager no access to family
   accounts, private conversations or anything beyond their existing permissions.

Where each rule lives:
- Rules 1-3: ENG-02 resolves the managers (roadmap §6.3) and writes one
  `chat.actor_block_manager_notice` row per manager.
- Rule 4: in the database, unique (`block_id`, `manager_staff_id`) on
  `chat.actor_block_manager_notice` (ENG-01). This replaces the single
  `actor_block.notified_manager_staff_id` column.
- Rule 5: ENG-02 writes a `block.created` audit row through the existing audit service.
- Rule 6: the notice table has RLS on, no policy and no grant to any request
  role (ENG-01). It is history, not a permission. ENG-02's notification carries
  only names and a link to the case, opened with the manager's existing permissions.

Recorded in the roadmap as A-2a (§1a), §6.2 and §6.3.

## ENG-03 (2026-11-06): Block API and server-side enforcement, as built

- **Routes:** `POST /me/blocks`, `GET /me/blocks`, `DELETE /me/blocks/:id` (self-service;
  staff, self, the official account, any department manager and the Super Admin are
  refused with 403 `COMM.BLOCK_NOT_ALLOWED` and a `reason`). Limit: `block.limit.per_blocker_day`.
- **One helper:** `apps/api/src/platform/blocks.ts` (`blockedBy`, `hasBlocked`, cached per request).
- **Hidden for the blocker only:** the blocked author's `text`/`image`/`video`/`voice`/`file`
  messages in the message page, pins, starred, search (never matched), forwards (refused as
  absent), the chat-list preview and attachment bytes (404). `system` and `card` never.
- **Not delivered to the blocker:** message pushes and Center entries (`message-audience.ts`),
  mentions, and Center entries whose author is blocked except the allowlist
  `BLOCK_EXEMPT_CATEGORIES` = lesson, payment, task, system (`notification-catalog.ts`).
  Realtime `message.created` carries no body for anyone; the blocker's copy is marked
  `hiddenByBlock`.
- **Calls:** a callee who blocked the caller is not seated (not rung); if nobody is left the
  caller gets 409 `COMM.CALL_UNAVAILABLE`. **A lesson call always rings.** A *lesson call*
  (`CallService.isLessonCall`) is: the caller is a teacher and the callee a parent; the
  conversation is about learners (`conversation.learner_id` or `conversation_learner`); one of
  them is in the callee's family and has a lesson with this teacher whose outcome is still open
  or `held`, from 15 minutes before its start to 15 minutes after its end, at the moment the
  call is started.
- **Direct conversations:** a blocked person cannot open (or reopen through
  `POST /conversations/direct`) a direct conversation with the blocker: 403 `COMM.DIRECT_BLOCKED`.
  Anyone else (the staff covering the family's direct conversation) is unaffected.
- **Managers:** `block_created_manager` (migration slot 20261106110000) to each manager whose
  notice row was newly written; family → each supervisor of the children → their department's
  manager; teacher → their PD-35 supervisor's department manager; the blocked person if one of
  them is skipped and every Super Admin told instead; nobody → every Super Admin.
- **Counts and queued pushes (ENG-03 follow-up):** unread counts (per conversation and the chat
  list's, so any total summed from it) never count a message the viewer's block hides; after an
  unblock those messages count as unread again (they were never read). A chat push queued before
  a block is re-checked when due (`guardDueMessages`): it goes only while it stands for an unread
  message the recipient may see, else it is cancelled with failure `BLOCKED`; a held summary
  drops the chats it no longer stands for; a waiting mention by someone the target since blocked
  is cancelled. Pushes carry no unread count (generic texts), so there is nothing else to correct.
