## 5. Ingest verification plan (step 5; the materials session implements it)

**Goal.** An unbroken chain of evidence:

> the Complex's page → the published archive hash → our downloaded archive → every extracted file → its (surah, ayah) → the stored object → the row in `chat.quran_ayah_audio`.

Every link is checked by machine. Any failure **stops** the ingest; nothing is ingested partially.

**Constants for the ingest.** A reviewed code change, never configuration:

| Constant | Value |
|---|---|
| `reciter_code` | `kfgqpc-huthify-hafs` (fits `isReciterCode`, `apps/api/src/quran/audio-key.ts`) |
| Source URL | `https://download.qurancomplex.gov.sa/new-sounds/huthify-01/hafs/huthify-ayat.rar` |
| Release page | `https://qurancomplex.gov.sa/quran-audio-hafs-huthify/` |
| Expected archive SHA-256 | `ad50fd0d8c362f6967141b5240cdbac4089efaf6d3a46ef159c3c8aaa05371f5` (compare case-insensitively) |
| Expected archive bytes | `842634506` |
| Text dataset for cross-check | `tanzil-uthmani-1.1`, pinned in `apps/api/src/quran/pinned.ts` (file SHA-256 `18c719bb…6fb1`) |

### Stage 0: provenance (before any byte is trusted)

1. **Gate:** the owner has approved the download in §2.1.
2. Re-capture the release page in the **same hour** as the download.
3. **Stop** if the published hash differs from the constant. A changed hash means a new release, and it needs a new review.
4. Record:
   - download start and end time (UTC);
   - the request URL and final URL;
   - HTTP status, `Content-Length`, `Last-Modified`, `ETag`;
   - the TLS certificate subject and issuer.

### Stage 1: the archive

1. SHA-256 of the downloaded file must equal the constant, and its size must equal `842634506`.
2. On a mismatch, **do not extract**. Delete the file, re-download once, and report.

### Stage 2: safe listing and extraction (untrusted data)

1. Use a fresh, empty directory outside the repo, and a pinned extractor version.
2. **List before extracting.** Reject the whole archive if any entry:
   - has an absolute path, `..`, or a drive letter;
   - is a symlink, hard link or device file;
   - is encrypted;
   - is larger than `MAX_AYAH_AUDIO_BYTES` (50,000,000);
   - or if the archive's total unpacked size exceeds 4 GB.
3. Extract with no overwriting. Execute nothing from the archive.

### Stage 3: mapping every file to (surah, ayah)

1. Derive the naming pattern from the **listing**, then write it into the ingest as a strict, anchored, reviewed regex.
   - The pattern is unknown today: no audio has been downloaded.
   - A `SSSAAA.mp3` layout is common, but **do not assume it**.
2. Classify each entry as exactly one of:
   - **mapped**: one (surah, ayah) with `1 ≤ surah ≤ 114` and `1 ≤ ayah ≤ ayahCount(surah)`;
   - **known extra**: a pattern the reviewer has listed by name, such as a stand-alone basmalah (`SSS000`) or an istiʿādha. Reported, **not** ingested;
   - **reject**, with one reason from: `unparsed-name`, `surah-out-of-range`, `ayah-out-of-range`, `duplicate-ayah` (two entries for one ayah, including case or folder variants), `not-audio`, `empty`.
3. Directory entries are ignored, but their names are logged.

### Stage 4: completeness against the verified text dataset

1. The set of mapped (surah, ayah) pairs must **equal exactly** the 6,236 keys of `tanzil-uthmani-1.1`:
   - 114 surahs;
   - each surah's count equals that surah's Tanzil count (the same counts as `materials/quran-surahs.ts`);
   - **missing = 0**.
2. Report `missing` and `extra` as explicit lists, never only as counts.

### Stage 5: per-file content checks

For every mapped file:
- SHA-256 and byte size;
- `ffprobe`: container, codec, sample rate, channels, bitrate and duration;
- a full decode (`ffmpeg -v error -i f -f null -`) with **zero** errors;
- `duration_ms > 0`.

**Format check.** `audioKey` stores `.mp3`.
- If the files are not MP3, **stop and report**.
- Transcoding waits for the Complex's answer to item (h), or for a written decision by the owner.

**Duration sanity.** Flag any ayah whose duration per letter of Tanzil text is more than 3 standard deviations from the reciter's mean. Flagged files go to the human check. They are **not** rejected automatically.

### Stage 6: is it really the right ayah? (human, signed)

A matching hash proves the file is the Complex's. It does **not** prove the Complex's file name is right.

A Quran teacher listens to:
- the first and last ayah of every surah (≤ 228 files);
- 100 random ayat, seeded and with the seed recorded;
- every stage-5 outlier;
- the fixed cases:
  - 1:1 (basmalah as an ayah);
  - 2:1 (muqaṭṭaʿāt);
  - 2:282 (the longest);
  - 9:1 (no basmalah);
  - 27:30 (basmalah inside an ayah);
  - 108:1–3;
  - all 15 sajda ayat.

**Basmalah.** For each surah except 1 and 9, confirm whether the first ayah's file **includes** the basmalah. Record the answer, because the player must not play it twice.

The teacher signs a sheet listing each file, the result (ok/wrong) and any note. **A single "wrong" stops the release** until it is explained.

## 8. Unresolved legal questions

1. **Does «مجاناً» exclude a paid service?** This is the core question; the letter asks it as item (a).
2. **Is the e-mail reply enough?**
   - Egyptian law asks for an itemised written authorisation (Law 82/2002 Art. 149 via Art. 159).
   - A general-inbox e-mail may not show who decided or their authority.
   - Item (i) asks for letterhead. Counsel decides whether the reply suffices.
3. **The reciter's performer rights.**
   - Sheikh Al-Hudhaify is living, and the grant is the producer's.
   - Nothing public shows that his performer rights (Egypt Art. 156; perpetual moral rights, Art. 155) are cleared through the Complex. The letter asks this as item (g).
4. **Law 102/1985 (Egypt).** Does in-app streaming or caching of Quran recordings need an Al-Azhar Islamic Research Academy licence, even for a foreign official recording? This is open and independent of KFGQPC (PR #190, D-2).
5. **Revocation and change.**
   - The grant has no term, and the Complex can change the page.
   - We do not know whether a withdrawal would bind files already downloaded.
   - Our protection is the dated, hashed captures. Counsel should advise whether to ask for a fixed-term letter.
6. **Saudi law governs the site.** Disputes about the site go to Saudi courts (privacy policy). It is unclear whether that clause reaches the audio grant itself. *(interpretation)*
7. **Transcoding and loudness.** Is conversion a "modification" that touches moral rights? It is asked as item (h). Until answered, we serve the files byte-identical.
8. **Register of dispositions (Egypt Art. 185, amended 2020).** Should a written permission be registered to be enforceable against third parties? Counsel decides (PR #190, D-1).
