Jawwid Chat — Project Brief for Implementation
Customer Success operating system inside the Jawwid app. Replaces WhatsApp for the CS team.
Full design doc (v3) exists separately; this brief is the contract for what to build.
0. The one rule
One Family → One Primary Owner. The Owner is not a bottleneck. The system — not the employee —
owns the family's history. People can change; the customer experience must not reset.
1. Operating model (decided — do not re-litigate)
Permanent Ownership + Configurable Coverage.

No shared queue. No automatic routing/distribution. No AI deciding priority.
One continuous thread per family (WhatsApp-like). Topics are cases layered on the thread.
Priority is not a stored field. It is a computed attention score from live signals, shown as a readable
reason.
Workload is a weighted sum of real work units. Number of families is never part of workload.
All thresholds/weights/windows live in a config table. Every number below is an initial hypothesis.
