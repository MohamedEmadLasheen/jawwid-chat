## 1. Authorized scope — and nothing else

1. `POST /api/v1/livekit/webhook` is exempt from the global bearer-token guard and is
   authenticated by LiveKit's own signature only (owner, 2026-10-15: "yes").
2. LiveKit's `application/webhook+json` body is captured as the signed raw bytes.
3. The regression test that proves 1–2 over real HTTP.

Out of scope: RT-037 join-time enforcement and media revocation, push privacy, the active-call
lifecycle (no timeout is introduced), call routing, CallKit / PushKit.

## 2. The defect (verified on this branch before any change)

| Id | Defect | Evidence |
|---|---|---|
| D4a / RT-038a | The global bearer guard answered **401 `AUTH.UNAUTHENTICATED`** to every LiveKit webhook — LiveKit authenticates with its own signature, not a Jawwid token — so the controller's signature check never ran | `livekit-webhook-http.spec.ts` against the unchanged code: 3 of 4 failed, every webhook case 401 from the guard |
| D4b / RT-038b | LiveKit posts `Content-Type: application/webhook+json`; no parser claimed it, so `rawBody` was never captured and a signed delivery was refused "no body" | the same test with only the guard fix applied: the `application/webhook+json` case still 401, the `application/json` case 200 |

Consequence: W5 media presence could never be updated by a running API; every earlier W5 test called
the verifier or the service directly.

## 3. What changed

| File | Change | Behavior change |
|---|---|---|
| `apps/api/src/communication/api/livekit-webhook.controller.ts` (W5) | `@Public()` on the controller | Signed LiveKit deliveries are processed. An unsigned or tampered one is still **401**, now from the controller's own signature check. No other route is affected. |
| `apps/api/src/infra/http/bootstrap.ts` | A raw-body middleware for `application/webhook+json` only — NOT `useBodyParser('json')`, which would replace Nest's JSON parser and break every JSON route (login included) | None for any other content type (tested: `application/json` still parses; a route without `@Public()` still requires a token) |
| `apps/api/test/integration/livekit-webhook-http.spec.ts` | New: the webhook through the real guard, Express parsers and controller | — |
